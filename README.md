# aiDigest — сбор кейсов внедрения ИИ

Команда «Аналитика» вручную ищет кейсы внедрения искусственного интеллекта на трёх уровнях: **мир**, **регионы РФ** и **Свердловская область**. По каждому кейсу она выписывает цифры «было → стало» и проверяет их по второму источнику. aiDigest делает эту работу автоматически: сервис находит свежие статьи, извлекает кейсы с цифрами и позволяет скачать таблицу Excel. В таблице всё, в чём система не уверена, помечено флагами.

Главный принцип: **цифра без дословной цитаты из статьи не считается проверенной.** Код сам ищет каждую цитату и каждое число в тексте статьи. Не нашёл — ставит флаг.

Как устроена проверка цитаты:
- цитата ищется в тексте целыми словами: «на 4» не находится внутри «на 45%»;
- в ней должно быть не меньше 3 слов, из них хотя бы 2 настоящих (не числа и не «млн руб.»);
- многоточие разрешено. Каждая часть ищется в тексте по порядку, части стоят не дальше 150 символов друг от друга, а в пропуск не должно попадать «не», «нет» или «без»;
- знак изменения («+23%» / «−23%») не должен противоречить словам цитаты («выросло» / «снизилось»);
- если LLM досчитала что-то сама (например, «стало 77%» из «снизилось на 23%»), досчитанное значение удаляется, а остаётся только то, что есть в цитате.

## Как устроен цикл

```
config/queries.yaml ──► 1. Поиск ──► статьи с полным текстом
                                                  │
                        2. Извлечение (LLM) ◄─────┘   есть ли в статье конкретный кейс?
                                │                    какие у него цифры и цитаты?
                        3. Проверка цитат (код) ──►  цитата и числа есть в тексте? нет → флаг
                                │
                        4. Дедупликация (LLM)  ──►  это новый кейс или уже известный?
                                │                    известный → объединить источники
                        5. Подтверждение (поиск + LLM + код)
                                │                    есть ли те же цифры в другом издании?
                        6. PostgreSQL ──► data/out/cases_ГГГГ-ММ-ДД.xlsx
```

- **Источники** берутся из справочника [`config/sources.yaml`](config/sources.yaml). Справочник меняется редко и правится вручную. По нему же определяется достоверность каждой ссылки.
- **Методика оценки** зависит от сектора и уровня кейса:

  | Сектор и уровень | Методика | Критерии |
  |---|---|---|
  | Госсектор в РФ (включая Свердловскую область) | **Р-1** | скорость, качество, объективность, экономическая эффективность, персонализация |
  | Госсектор за рубежом | **М-1** | результат услуги, качество и надёжность, производительность и труд, опыт и доступность, доверие, реализуемость и масштаб |
  | Бизнес, любой уровень | **бизнес-метрики** | ROI, операционные затраты, время процесса, уровень ошибок |

- **База** `PostgreSQL` копится от запуска к запуску. Повторный запуск добавляет новые кейсы и обновляет найденные совпадения, а уже знакомые статьи заново не обрабатывает.

Подробности решений — в [design-документе](docs/superpowers/specs/2026-11-07-ai-cases-pipeline-design.md) и [плане реализации](docs/superpowers/plans/2026-11-07-ai-cases-pipeline.md).

## Разработка

Нужны Python 3.12+, Node.js 22 и Docker Compose. Пример для Git Bash в Windows.

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.lock -e . --no-deps
docker compose -f docker-compose.dev.yml up -d
.venv/Scripts/python -m aidigest_api
```

Во втором терминале:

```bash
cd frontend
npm ci
npm run dev
```

Откройте `http://localhost:5173`. Vite направляет запросы API на `http://127.0.0.1:8000`. Для другого адреса БД задайте `DATABASE_URL`. При старте API применит миграции.

Для локальной разработки задайте параметры в `secrets.env` в корне проекта или в окружении. Для входа нужны `WEB_USERNAME`, `WEB_PASSWORD` и постоянный `WEB_SECRET_KEY`. Локально вход можно отключить, оставив `WEB_PASSWORD` пустым. Для сбора через Яндекс задайте `YANDEX_SEARCH_API_KEY` и `YANDEX_SEARCH_FOLDER_ID`, а для LiteLLM — `LITELLM_API_KEY` и `LITELLM_BASE_URL`. Для поиска через Tavily задайте `AIDIGEST_SEARCH_PROVIDER=tavily` в окружении и заполните `TAVILY_TOKEN`. См. [инструкцию установки](docs/deploy.md).

## Веб-интерфейс для «Аналитики»

В разделе «Кейсы» можно фильтровать список, открывать карточки с цитатами и скачивать Excel. На странице «Запуск» видны состояние сбора, лог и история. Сбор продолжает работать после закрытия страницы. Перезапуск бэкенда прерывает сбор, уже сохранённые кейсы остаются в базе. PostgreSQL допускает один активный сбор.

Для отладки локального API с отключённым входом можно запустить сбор с меньшим бюджетом:

```bash
curl -fsS http://localhost:8000/api/runs -H 'Content-Type: application/json' \
  -d '{"budget":5,"levels":["Свердловская область"]}'
```

Поле `days` задаёт окно свежести. С `offline: true` сбор использует кеш для поиска и извлечения. В офлайн-режиме сбор не проверяет месячный лимит.

## Лимиты и как их не сжечь

- **Бюджет запуска** ограничивает количество новых поисковых запросов. Для Яндекса окно свежести относится к дате добавления страницы в поиск. Текст статьи скачивается по её URL, при недоступности используется фрагмент выдачи.
- **Tavily: 1000 кредитов в месяц на всё**, включая отладку. Один поисковый запрос стоит 1 кредит (при любом числе результатов — сейчас 10 на запрос).
- **Фактический расход и остаток берутся у Tavily** через бесплатный `GET /usage`. Бюджет запуска сокращается до реального остатка, а при нулевом остатке новый сбор блокируется. При недоступности `/usage` расход показывается как неизвестный, и сбор ограничивается заданным бюджетом.
- **Как делится бюджет запуска:**
  - 60% уходит на сбор статей: 14 запросов из `config/queries.yaml`;
  - 40% заранее отложены на подтверждение, сбор их не трогает;
  - если на сборе остались кредиты, они переходят к подтверждению, но не наоборот.
- **Когда бюджет кончается,** запуск не падает. Уже найденное обрабатывается и сохраняется, а неподтверждённые кейсы получают флаг `подтверждение_не_проводилось` и проверяются в следующий раз.
- **Кеш `data/cache/` экономит кредиты.** Ответы поиска, LLM и тексты статей сохраняются на диск, и повтор того же запроса бесплатен. Не удаляйте кеш без нужды.
- **Правка промпта сбрасывает кеш LLM.** После изменения промпта в `src/aidigest/extract.py`, `confirm.py` или `dedup.py` соответствующие ответы LLM будут запрошены заново.

## Что в Excel-таблице

**Лист «Кейсы»** — одна строка на кейс. У общероссийских кейсов без конкретного региона в колонке «Регион» стоит «федеральный уровень». Сначала идут кейсы с цифрами, внутри них — подтверждённые, затем с противоречием, затем из одного источника.
Колонки: уровень, страна, регион, организация, сектор, отрасль, технология ИИ, название, суть, стадия, методика, показатели, статус подтверждения, флаги, источники с достоверностью, даты.

**Лист «Показатели»** — одна строка на цифру: было / стало / изменение, единица, факт или план, **дословная цитата**, источник, прошла ли цитата проверку, какие источники её подтвердили и какие с ней расходятся.

Отчёты о выполненных сборах доступны в истории на странице «Запуск».

### Стадии внедрения
`в разработке` → `пилот` → `внедрён` → `масштабирование`. Если по статье стадию понять нельзя — `неизвестно`.

### Статусы подтверждения

| Статус | Значение |
|---|---|
| `подтверждено` | хотя бы одна цифра найдена в другом, независимом издании. Подтверждение засчитывается двумя путями: LLM нашла совпадение и её цитата содержит те же числа, или код сам нашёл в статье предложение со всеми числами показателя (хотя бы одно больше 10), словом из названия показателя, а статья упоминает место или организацию кейса |
| `противоречие` | другое издание называет другое значение того же показателя в той же единице (обе цифры сохранены) |
| `один_источник` | второго источника пока нет |

### Флаги

| Флаг | Что значит | Что делать |
|---|---|---|
| `цифра_не_найдена_в_тексте` | цитаты или числа LLM нет в статье — возможно, LLM ошиблась или досчитала цифру сама | проверить по ссылке вручную, не использовать без проверки |
| `противоречие_источников` | источники расходятся в цифрах | сравнить обе версии |
| `один_источник` | подтверждение искали, но не нашли | цифра может быть верной, но не перепроверена |
| `подтверждение_не_проводилось` | на подтверждение не хватило кредитов | следующий запуск проверит сам |
| `нет_измеримых_показателей` | кейс есть, цифр нет | годится как пример, не как измеримый кейс |
| `стадия_неясна` | из статьи не понять стадию | уточнить по другим материалам |
| `источник_не_оценён` | домена нет в справочнике | при необходимости добавить домен в `config/sources.yaml` |

## Настройка

| Файл | Что в нём |
|---|---|
| [`config/sources.yaml`](config/sources.yaml) | справочник источников: домены, уровень, достоверность (`высокая` / `средняя` / `низкая`), тип, частота обновления. Источник без уровня (`level: null`) — общероссийское СМИ: оно используется для регионов РФ и Свердловской области |
| [`config/queries.yaml`](config/queries.yaml) | поисковые запросы по уровням. `use_registry_domains: true` ищет только по доменам справочника этого уровня, `false` ищет по всему интернету |
| [`config/settings.yaml`](config/settings.yaml) | бюджеты (`run_budget: 50`, `first_run_budget: 100`, `confirm_share: 0.4`), окно свежести, число результатов на запрос, длина статьи для LLM, правила повторного подтверждения (не чаще раза в 28 дней, не больше 2 повторов) |

Каждый новый запрос в `queries.yaml` добавляет 1 кредит к каждому запуску.

## Эталон

[`eval/reference_cases.yaml`](eval/reference_cases.yaml) содержит 3 кейса «Аналитики»: Челябинск (пробки и ДТП), Белгород (цифровой двойник водоснабжения) и Татарстан («ГосПромпт»). К ним 7 статей и 8 ожидаемых цифр. Команда `eval` проверяет, вытаскивает ли LLM эти цифры с подтверждёнными цитатами. Сейчас она находит **7 из 8** (не извлекается охват «230 объектов»).

Если статья не скачивается (защита от ботов, сертификат), сохраните её текст вручную в `eval/texts/<id>-<номер ссылки с 0>.txt`. Например, `eval/texts/tatarstan-gosprompt-0.txt`.

Запускайте `eval` после любой правки промпта: так видно, не стало ли хуже.

## Известные ограничения

- **Отсев «не-кейсов» неидеален.** LLM помечает опросы, обзоры, планы и статистику как не конкретное внедрение, но иногда ошибается в обе стороны. Причины отсева видны в логе запуска.
- **Критерий «прочее» встречается часто.** Обычно это показатели охвата (число обращений, пользователей, регионов) и отраслевые показатели: в методиках «Аналитики» для них нет критерия. Это вопрос к «Аналитике»: возможно, стоит добавить критерий «охват/масштаб».
- **Пересказанные цитаты не проходят проверку.** Если LLM переставила или выкинула слова из фразы статьи, цифра получает флаг `цифра_не_найдена_в_тексте`, даже если сама цифра верна. Это осознанная строгость.
- **Эталон не совпадает с документом «Аналитики» один к одному.** Их исходные ссылки не нашлись, поэтому взяты статьи с теми же цифрами.
- **Отложенные замечания ревью:**
  - перепутанные «было» и «стало» не проверяются;
  - `www.` и порядок параметров в ссылках не нормализуются;
  - кириллические домены уходят в Tavily не в punycode;
  - попытка подтверждения засчитывается даже при ошибке LLM.
- Нет Яндекс.Поиска и FRIDA: доступа пока нет, но поиск и сравнение кейсов вынесены в отдельные модули, чтобы подключить их позже.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| В отчёте «Статей с ошибкой LLM» больше нуля | LLM не ответила или ответила не в том формате. Эти статьи не помечены обработанными и повторятся при следующем запуске. Подробности — в сообщениях `Статья пропущена` |
| `eval --offline` падает | нужного ответа LLM нет в кеше (например, после правки промпта). Запустите `eval` без `--offline` |
| `Не заданы настройки доступа к поиску` | заполните ключи выбранного провайдера в `secrets.env` или окружении |
| Кириллица в консоли превращается в знаки вопроса | CLI сам переключает вывод на UTF-8. Если запускаете свой скрипт, вызовите `sys.stdout.reconfigure(encoding="utf-8")` |
