# aiDigest — сбор кейсов внедрения ИИ

Команда «Аналитика» вручную ищет кейсы внедрения искусственного интеллекта на трёх уровнях: **мир**, **регионы РФ** и **Свердловская область**. По каждому кейсу она выписывает цифры «было → стало» и проверяет их по второму источнику. aiDigest делает эту работу автоматически: одна команда находит свежие статьи, достаёт из них кейсы с цифрами и выгружает Excel-таблицу. В таблице всё, в чём система не уверена, помечено флагами.

Главный принцип: **цифра без дословной цитаты из статьи не считается проверенной.** Код сам ищет каждую цитату и каждое число в тексте статьи. Не нашёл — ставит флаг.

---

## Как устроен цикл

```
config/queries.yaml ──► 1. Поиск (Tavily) ──► статьи с полным текстом
                                                  │
                        2. Извлечение (LLM) ◄─────┘   есть ли в статье конкретный кейс?
                                │                    какие у него цифры и цитаты?
                        3. Проверка цитат (код) ──►  цитата и числа есть в тексте? нет → флаг
                                │
                        4. Дедупликация (LLM)  ──►  это новый кейс или уже известный?
                                │                    известный → объединить источники
                        5. Подтверждение (Tavily + LLM + код)
                                │                    есть ли те же цифры в другом издании?
                        6. data/cases.json ──► data/out/cases_ГГГГ-ММ-ДД.xlsx
```

- **Источники** берутся из справочника [`config/sources.yaml`](config/sources.yaml). Справочник меняется редко и правится вручную. По нему же определяется достоверность каждой ссылки.
- **Методика оценки** зависит от сектора и уровня кейса:

  | Сектор и уровень | Методика | Критерии |
  |---|---|---|
  | Госсектор в РФ (включая Свердловскую область) | **Р-1** | скорость, качество, объективность, экономическая эффективность, персонализация |
  | Госсектор за рубежом | **М-1** | результат услуги, качество и надёжность, производительность и труд, опыт и доступность, доверие, реализуемость и масштаб |
  | Бизнес, любой уровень | **бизнес-метрики** | ROI, операционные затраты, время процесса, уровень ошибок |

- **База** `data/cases.json` копится от запуска к запуску. Повторный запуск дописывает только новые кейсы, а уже знакомые статьи заново не обрабатывает.

Подробности решений — в [design-документе](docs/superpowers/specs/2026-11-07-ai-cases-pipeline-design.md) и [плане реализации](docs/superpowers/plans/2026-11-07-ai-cases-pipeline.md).

## Установка

Нужен Python 3.12 или новее (проверено на 3.13). Команды ниже — для Git Bash в Windows.

```bash
python -m venv .venv
```

```bash
.venv/Scripts/python -m pip install -e ".[dev]"
```

Затем в корне проекта нужны два файла с ключами. **Эти файлы не коммитятся (они в `.gitignore`) и никому не пересылаются.**

| Файл | Ключи |
|---|---|
| `litellm.env` | `LITELLM_API_KEY`, `LITELLM_BASE_URL`, по желанию `LITELLM_MODEL` (иначе `GigaChat-3-Pro`) |
| `tavily.env` | `TAVILY_TOKEN` |

Формат — строки `КЛЮЧ=значение`, кавычки вокруг значения допускаются. Строки, начинающиеся с `#`, считаются комментариями.

Проверить, что всё установилось, можно тестами. Они не ходят в сеть и не тратят ни кредитов, ни вызовов LLM:

```bash
.venv/Scripts/python -m pytest -q
```

## Запуск

| Команда | Что делает | Расход |
|---|---|---|
| `.venv/Scripts/python -m aidigest run` | обычный регулярный цикл, например раз в неделю | до 30 кредитов Tavily |
| `.venv/Scripts/python -m aidigest run --first-run` | первый запуск на пустой базе: там больше кейсов, которым нужно подтверждение | до 100 кредитов |
| `.venv/Scripts/python -m aidigest run --budget 5 --levels "Свердловская область"` | отладка: свой лимит и только нужные уровни | до 5 кредитов |
| `.venv/Scripts/python -m aidigest run --offline --budget 0` | повтор только по кешу, без внешних вызовов | 0 |
| `.venv/Scripts/python -m aidigest export` | пересобрать Excel из базы без поиска | 0 |
| `.venv/Scripts/python -m aidigest eval --fetch-only` | скачать тексты эталонных статей обычным HTTP | 0 |
| `.venv/Scripts/python -m aidigest eval` | проверить качество извлечения на эталоне | ~7 вызовов LLM |
| `.venv/Scripts/python -m aidigest eval --offline` | то же по кешу | 0 |

Параметры `run`:
- `--levels` — уровни через запятую: `мир`, `регионы РФ`, `Свердловская область` (по умолчанию все);
- `--days N` — окно свежести материалов в днях (по умолчанию 30);
- `--budget N` — лимит кредитов на запуск (перекрывает `--first-run`).

После `run` в консоли печатается отчёт: сколько потрачено кредитов, сколько обработано статей, сколько найдено новых кейсов, сколько проведено и отложено подтверждений, а также сводка по флагам. Таблица сохраняется в `data/out/cases_ГГГГ-ММ-ДД.xlsx`.

## Лимиты и как их не сжечь

- **Tavily: 1000 кредитов в месяц на всё**, включая отладку. Один поисковый запрос стоит 1 кредит.
- **Как делится бюджет запуска:**
  - 60% уходит на сбор статей: 12 запросов из `config/queries.yaml`;
  - 40% заранее отложены на подтверждение, сбор их не трогает;
  - если на сборе остались кредиты, они переходят к подтверждению, но не наоборот.
- **Когда бюджет кончается,** запуск не падает. Уже найденное обрабатывается и сохраняется, а неподтверждённые кейсы получают флаг `подтверждение_не_проводилось` и проверяются в следующий раз.
- **Кеш `data/cache/` экономит кредиты.** Все ответы Tavily, LLM и HTTP сохраняются на диск, и повтор того же запроса бесплатен. Не удаляйте кеш без нужды.
- **Правка промпта сбрасывает кеш LLM.** После изменения промпта в `src/aidigest/extract.py`, `confirm.py` или `dedup.py` соответствующие ответы LLM будут запрошены заново.
- Месячного счётчика нет: следите за строкой «Кредитов Tavily потрачено» в отчётах.

## Что в Excel-таблице

**Лист «Кейсы»** — одна строка на кейс. Сначала идут кейсы с цифрами, внутри них — подтверждённые, затем с противоречием, затем из одного источника.
Колонки: уровень, страна, регион, организация, сектор, отрасль, технология ИИ, название, суть, стадия, методика, показатели, статус подтверждения, флаги, источники с достоверностью, даты.

**Лист «Показатели»** — одна строка на цифру: было / стало / изменение, единица, факт или план, **дословная цитата**, источник, прошла ли цитата проверку, какие источники её подтвердили и какие с ней расходятся.

**Лист «Отчёт запуска»** — тот же отчёт, что печатается в консоли.

### Стадии внедрения
`в разработке` → `пилот` → `внедрён` → `масштабирование`. Если по статье стадию понять нельзя — `неизвестно`.

### Статусы подтверждения

| Статус | Значение |
|---|---|
| `подтверждено` | хотя бы одна цифра найдена в другом, независимом издании, и это подтверждает цитата с тем же числом |
| `противоречие` | другое издание называет другое значение того же показателя (обе цифры сохранены) |
| `один_источник` | второго источника пока нет |

### Флаги

| Флаг | Что значит | Что делать |
|---|---|---|
| `цифра_не_найдена_в_тексте` | цитаты или числа LLM нет в статье — возможно, LLM ошиблась или досчитала цифру сама | проверить по ссылке вручную, не использовать без проверки |
| `противоречие_источников` | источники расходятся в цифрах | сравнить обе версии |
| `один_источник` | подтверждение искали, но не нашли | цифра может быть верной, но не перепроверена |
| `подтверждение_не_проводилось` | на подтверждение не хватило кредитов | следующий запуск проверит сам |
| `нет_измеримых_показателей` | кейс есть, цифр нет | годится как пример, не как измеримый кейс |
| `стадия_неясна` | из статьи не понять стадию | уточнить по другим материалам |
| `источник_не_оценён` | домена нет в справочнике | при необходимости добавить домен в `config/sources.yaml` |

## Настройка

| Файл | Что в нём |
|---|---|
| [`config/sources.yaml`](config/sources.yaml) | справочник источников: домены, уровень, достоверность (`высокая` / `средняя` / `низкая`), тип, частота обновления. Источник без уровня (`level: null`) — общероссийское СМИ: оно используется для регионов РФ и Свердловской области |
| [`config/queries.yaml`](config/queries.yaml) | поисковые запросы по уровням. `use_registry_domains: true` ищет только по доменам справочника этого уровня, `false` ищет по всему интернету |
| [`config/settings.yaml`](config/settings.yaml) | бюджеты (`run_budget: 30`, `first_run_budget: 100`, `confirm_share: 0.4`), окно свежести, число результатов на запрос, длина статьи для LLM, правила повторного подтверждения (не чаще раза в 28 дней, не больше 2 повторов) |

Каждый новый запрос в `queries.yaml` добавляет 1 кредит к каждому запуску.

## Эталон

[`eval/reference_cases.yaml`](eval/reference_cases.yaml) содержит 3 кейса «Аналитики»: Челябинск (пробки и ДТП), Белгород (цифровой двойник водоснабжения) и Татарстан («ГосПромпт»). К ним 7 статей и 8 ожидаемых цифр. Команда `eval` проверяет, вытаскивает ли LLM эти цифры с подтверждёнными цитатами. Сейчас она находит **7 из 8** (не извлекается охват «230 объектов»).

Если статья не скачивается (защита от ботов, сертификат), сохраните её текст вручную в `eval/texts/<id>-<номер ссылки с 0>.txt`. Например, `eval/texts/tatarstan-gosprompt-0.txt`.

Запускайте `eval` после любой правки промпта: так видно, не стало ли хуже.

## Известные ограничения

- **По Свердловской области пока мало кейсов: 3 из 54 в первом запуске.** Поисковые запросы для этого уровня нужно доработать.
- **LLM иногда принимает за кейс то, что кейсом не является.** Например, план закупок отрасли. Такие строки обычно без подтверждения, но их стоит просматривать.
- **У бизнес-кейсов часто стоит критерий «прочее», у федеральных кейсов не указан регион.**
- **Эталон не совпадает с документом «Аналитики» один к одному.** Их исходные ссылки не нашлись, поэтому взяты статьи с теми же цифрами.
- **Отложенные замечания ревью:**
  - знак изменения не проверяется (`+23%` проходит против «снизилось на 23%»);
  - нет минимальной длины цитаты;
  - `www.` и порядок параметров в ссылках не нормализуются;
  - кириллические домены уходят в Tavily не в punycode;
  - попытка подтверждения засчитывается даже при ошибке LLM.
- Нет Яндекс.Поиска и FRIDA: доступа пока нет, но поиск и сравнение кейсов вынесены в отдельные модули, чтобы подключить их позже.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Excel сохранился как `cases_ГГГГ-ММ-ДД_ЧЧММСС.xlsx` | файл за этот день был открыт в Excel — данные не потеряны, это просто другое имя |
| В отчёте «Статей с ошибкой LLM» больше нуля | LLM не ответила или ответила не в том формате. Эти статьи не помечены обработанными и повторятся при следующем запуске. Подробности — в сообщениях `Статья пропущена` |
| `run --offline` ничего не нашёл | ключ кеша поиска содержит дату начала окна свежести. На следующий день офлайн-запуск запросов не находит. Повторяйте офлайн в тот же день или используйте `export` |
| `eval --offline` падает | нужного ответа LLM нет в кеше (например, после правки промпта). Запустите `eval` без `--offline` |
| `Не найден файл litellm.env` / `tavily.env` | положите файлы с ключами в корень проекта (см. «Установка») |
| Кириллица в консоли превращается в знаки вопроса | CLI сам переключает вывод на UTF-8. Если запускаете свой скрипт, вызовите `sys.stdout.reconfigure(encoding="utf-8")` |
