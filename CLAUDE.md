# CLAUDE.md — проект aiDigest

## Кто мы и что делаем

Мы — студенческая техническая команда (проектная практика, проекты Минцифры). Наша задача — **автоматизировать с помощью ИИ работу других студенческих команд**. В этом проекте наш «заказчик» — команда **«Аналитика»**, которая собирает кейсы внедрения ИИ и новости о них.

Формат итогового продукта ещё **не определён** — можно и нужно предлагать варианты. Рабочая гипотеза: **Python-пайплайн**, который потом раскатывается на сервере. Формат выдачи для «Аналитики» (таблица, дайджест, отчёт) тоже пока не согласован — делаем так, чтобы выход легко конвертировался (структурированные данные → любой формат).

Общение с пользователем и комментарии в коде — на русском.

## Процесс команды «Аналитика» (что автоматизируем)

Источник: `Вводные данные/dialogWithTeamLead.md`.

1. **Поиск источников** о тенденциях и кейсах внедрения ИИ на трёх уровнях: **мировой**, **РФ (субъекты)**, **Свердловская область**. Все три уровня одинаково приоритетны.
2. **Классификация источников**: достоверность, тип получаемой информации, частота обновления.
3. **Методика эффективности**: из НПА, указов, стратегий выделить измеримые показатели (KPI), по которым видно, как ИИ повлиял на процесс. Набор показателей свой для каждого уровня.
4. **Выход — кейс**: внедрение ИИ с измеримыми показателями эффекта (фактического, или ожидаемого, если проект в разработке) + **стадия внедрения** (в разработке / пилот / внедрён / масштабирование).
5. **Глубинная аналитика**: в исходных источниках часто мало цифр, поэтому по тому же кейсу нужно искать данные в других источниках (в т.ч. не из списка) и сверять цифры между ними.

### Методики оценки эффекта (из презентации)

- **Федеральный уровень** — KPI Национальной стратегии развития ИИ (Указ Президента № 490, п. 28.1): прирост ВВП за счёт ИИ, объём услуг по ИИ, публикации, выпускники, доля работников с навыками ИИ, доверие граждан, готовность отраслей, затраты организаций на ИИ (база 2022 → цель 2030). Плюс показатели «цифровой зрелости» госуправления (протокол президиума Правкомиссии от 24.09.2026 № 38).
- **Бизнес-уровень** — ROI = (выгода − затраты) / затраты × 100%; снижение операционных затрат; сокращение времени процесса; уровень ошибок.
- **М-1 (мир, госсектор)** — синтез 5 измерений OECD и 7 категорий UK AI Impact Evaluation Framework: результат услуги, качество и надёжность, производительность и труд, опыт и доступность, доверие и распределение эффекта, реализуемость и масштаб.
- **Р-1 (регионы РФ)** — адаптация модели Сбера «Оценка эффектов от внедрения ИИ в регионах»: **скорость, качество, объективность, экономическая эффективность, персонализация**; базовое и проектное значение. Критерии выбираются по цели процесса, а не применяются механически.

### Эталонные кейсы (`рос и рег.docx`)

Показывают, что значит «хороший кейс»: конкретный регион и отрасль, цифры «было → стало», и **подтверждение из второго источника**. Пример: Челябинская обл., компьютерное зрение на дорогах — время в пробках 13 → 5 мин (gubernia74.ru), ДТП 161 → 122 (chel.kp.ru, дублирующий источник). Татарстан, «ГосПромпт» — пример ранней стадии (426 госслужащих из 25 ведомств на старте).

## Пайплайн `aidigest` (как запускать)

Design: `docs/superpowers/specs/2026-11-07-ai-cases-pipeline-design.md`, план: `docs/superpowers/plans/2026-11-07-ai-cases-pipeline.md`.

```bash
.venv/Scripts/python -m pytest -q                       # тесты (без сети)
.venv/Scripts/python -m aidigest run                    # регулярный цикл (~30 кредитов Tavily)
.venv/Scripts/python -m aidigest run --budget 5 --levels "Свердловская область"   # отладка
.venv/Scripts/python -m aidigest run --offline --budget 0                         # только кеш
.venv/Scripts/python -m aidigest export                 # Excel из базы без поиска
.venv/Scripts/python -m aidigest eval --offline         # эталон из кеша (без вызовов LLM)
```

- База кейсов — `data/cases.json` (в git), выгрузки — `data/out/`, кеш Tavily/LLM/HTTP — `data/cache/` (не в git; не удалять без нужды — это сэкономленные кредиты).
- Конфиги: `config/sources.yaml` (справочник источников), `config/queries.yaml` (запросы), `config/settings.yaml` (бюджеты).
- Эталон: `eval/reference_cases.yaml`; ручные тексты статей — `eval/texts/<id>-<n>.txt`.
- Любая правка промпта (`extract.py`, `confirm.py`, `dedup.py`) сбрасывает кеш LLM для этих вызовов.
- В промпт нельзя вставлять примеры с конкретными цитатами — GigaChat копирует их дословно.

## Веб-интерфейс `aidigest_web`

Design: `docs/superpowers/specs/2026-11-07-web-frontend-design.md`. Flask + Jinja2, свой CSS без фреймворков, сервер waitress; extra `[web]`.
- **Не менять `src/aidigest/` ради фронта**: фронт только читает (модели, `CaseStore`, `export_xlsx`, `MonthlyUsage`) и запускает сбор отдельным процессом через `aidigest_web.runner`.
- `web.env` (`WEB_PASSWORD`, `WEB_SECRET_KEY`) — не читать и не выводить, как остальные `*.env`.
- Состояние запусков — `data/web/` (не в git). Запуск: `python -m aidigest_web` (localhost) или с `--host 0.0.0.0` только при заданном пароле.
- Для проверки в браузере — `.claude/launch.json` (конфигурация `aidigest-web`). Кнопку «Запустить сбор» при проверке не нажимать — это расход кредитов.

## Правила

- **`litellm.env` и `tavily.env` НИКОГДА не читать, не выводить, не коммитить и не отправлять куда-либо.** Код может загружать их в рантайме, но Claude не открывает эти файлы и не печатает их содержимое. То же для любых будущих файлов с ключами.
- **Учёт кредитов Tavily — `data/credits.json`.** `aidigest run` пишет туда сам; любой расход мимо `run` (пробные скрипты) дописывать вручную через `aidigest.usage.MonthlyUsage.record`.
- **Tavily — 1000 запросов в месяц.** Использовать только для отладки пайплайна, экономно (кешировать ответы на диск, не гонять повторно одни и те же запросы). Информацию для самой разработки (документация, поиск источников, ссылки на эталонные кейсы) Claude ищет своими средствами (WebSearch/браузер), а не через Tavily.
- **LLM через LiteLLM** — тоже только для отладки пайплайна; лимиты есть, но не критичные. Разработку (промпты, код) делает Claude.
- Процесс разработки — через skills superpowers (brainstorming → writing-plans → реализация с TDD).
- Секреты — только через env-файлы/переменные окружения, не в коде и не в логах.
- Любая цифра в кейсе должна иметь ссылку на источник. LLM не должна «додумывать» показатели: нет цифры в тексте — поле пустое.
- Кириллица в путях (`Вводные данные/`) — пути всегда в кавычках.
- Стек по умолчанию — Python. Перед добавлением тяжёлых зависимостей — обсудить.
