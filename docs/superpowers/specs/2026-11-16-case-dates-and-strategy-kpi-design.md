# Даты кейсов и показатели Национальной стратегии развития ИИ

## Задача

«Аналитике» нужно видеть, насколько свежи сведения о внедрении ИИ, и находить кейсы по решаемой задаче. В списке кейсов пользователь сможет выбрать обычный критерий эффекта или официальный KPI и перейти к результатам, источникам и обоснованию связи в карточке.

В первый выпуск входит пункт 28.1 Национальной стратегии развития ИИ, утверждённой Указом Президента РФ от 10.10.2019 № 490. Основа справочника — полный перечень показателей пункта 28.1 по [Указу от 15.02.2024 № 124](https://publication.pravo.gov.ru/document/0001202402150063). Поиск по конкретному министерству и показатели других документов выходят за рамки первого выпуска. Раздел «Источники» в карточке показывает отдельные публикации. Общий справочник источников описывает сайты и организации.

## Рассмотренные подходы

- **Автоматическая привязка по справочнику — согласованный вариант.** Модель предлагает идентификатор KPI и основание связи по тексту публикации. Пайплайн проверяет идентификатор, наличие цитаты и принадлежность источника кейсу. Это позволяет размечать новые кейсы в процессе сбора и дозаполнять старые без отдельного интерфейса.
- **Ручная разметка аналитиком.** Даёт аналитику контроль над спорными соответствиями и требует интерфейса редактирования и обработки каждого кейса. Её можно рассмотреть после проверки качества автоматической привязки.

## Список и карточка кейса

- Колонка «Обновлён» занимает место колонки «В базе с». На экране она отображает дату в формате `ДД.ММ.ГГГГ` и сортируется по дате. В карточке та же дата видна рядом с основными сведениями. Дату первого появления в базе можно по-прежнему посмотреть в карточке.
- Вместо «Главной цифры» в колонке «Показатели» выводится список показателей кейса с названиями и доступными значениями «было → стало» или величиной изменения. Первый экран ячейки показывает до трёх строк, остальные раскрываются по кнопке «Ещё N». Непроверенные цифры сохраняют пометку. Краткие названия связанных KPI показываются вместе с показателями. Список без показателей и связей отображает прочерк.
- Фильтр «Тип эффекта» использует критерии действующих методик, например «Скорость» или «Уровень ошибок». Фильтр «KPI Стратегии» использует официальный справочник. Если выбраны оба фильтра, кейс должен соответствовать обоим. Фильтрация выполняется по всему набору показателей и связей, включая свёрнутые строки. Выбор сохраняется в URL и сочетается с существующими фильтрами. При выбранном KPI кейсы с подтверждённой материалами связью без числовой метрики видны, когда выключен фильтр «только с цифрами». По умолчанию при выбранном KPI этот флажок выключен, без KPI — включён. Явно переданное значение `metrics=0` или `metrics=1` имеет приоритет.
- В разделе «Показатели» карточки сохраняются фактические и ожидаемые значения, цитаты и ссылки на источники. Для каждой привязки показываются название KPI, подпункт Стратегии, объяснение применимости и ссылка на публикацию. Общенациональные целевые значения относятся к Стратегии. Значения фактического или ожидаемого эффекта кейса берутся из его публикаций.
- Рядом с каждой публикацией в карточке показывается дата в формате `ДД.ММ.ГГГГ` или «Дата публикации не указана».

## Данные и обработка

### Дата кейса и источника

Используем существующее поле `Case.updated` в карточке и API списка. При создании это дата добавления кейса. При дальнейшем сборе дата меняется при изменении отображаемых сведений: стадии, источников или их дат, показателей и их подтверждений, статуса подтверждения по результатам проверки источников либо связей с KPI. Технические счётчики, повторная обработка тех же сведений и проверка без новых свидетельств дату не меняют. Для старых кейсов используем сохранённую дату, поскольку прежние изменения невозможно восстановить по истории.

Используем существующее поле `Source.published_at`. Пайплайн принимает корректную дату публикации из метаданных результата поиска. При её отсутствии можно принять явно обозначенную дату публикации того же материала из доступного текста, если исходная строка найдена в источнике. Дата события, дата обновления страницы и дата обработки кейса для этого поля не подходят. Приводим известные даты к календарной дате ISO. Метаданные и текст используются и при сборе, и при поиске подтверждений. При повторной встрече того же URL известная дата дополняет пустое поле. Для архива используем уже сохранённые даты и доступные результаты кеша. Формат старых значений и `null` учитывается при чтении.

### Справочник и связь с кейсом

Храним версионируемый справочник с устойчивыми идентификаторами, названиями для интерфейса, полными формулировками, подпунктами, ссылкой на первоисточник и критериями сопоставления. Сверяем перечень с Указом, включая показатель вычислительной мощности. Презентация «Аналитики» служит ориентиром.

Кейс может иметь несколько связей. Каждая хранит ID из справочника, объяснение, URL источника и проверяемую цитату. Если связь подтверждается уже извлечённым показателем, объяснение называет его. Смысл связи — основание рассматривать кейс в подборке по KPI, например обучение работников работе с ИИ. Само участие работников в пилоте без сведений об освоении навыков такого основания не даёт. Кейс без достаточных сведений остаётся без связи. Зарубежные кейсы проходят те же проверки применимости с учётом указанного в формулировке KPI охвата. Общие эффекты, например сокращение времени обработки заявки, остаются доступны через критерии эффекта. Сам по себе такой эффект не подтверждает прирост ВВП.

Сопоставление проводится отдельным кешируемым вызовом LLM по существующим данным кейса. Допустимое свидетельство — доступный текст публикации или ранее проверенная цитата (`quote_verified`). Это правило действует и для архива. Для каждой позиции справочник задаёт требования к географии и виду свидетельства. Промпт требует сверить смысл цитаты с этими требованиями и вернуть вид свидетельства, отрывок и обоснование. Пайплайн проверяет ID, допустимость вида свидетельства и уровня, принадлежность URL к кейсу и наличие отрывка в материалах указанного источника. Смысловую применимость оценивает модель по правилам справочника. Эталонные сценарии включают подходящие и слабые связи, например обучение сотрудников и простое участие в пилоте.

Повторная разметка добавляет новые свидетельства или уточняет существующие по паре KPI и URL. Пустой ответ или отсутствие прежнего текста в текущем пакете сохраняет уже принятые связи. Если ответ частично валиден, сохраняются прошедшие проверку связи, остальные отклоняются. В карточке несколько свидетельств об одном KPI группируются, в фильтре учитывается сам KPI. Сопоставление повторяется при изменении используемых сведений или неуспешной предыдущей попытке. Повтор с теми же входными данными использует кеш. При одинаковом результате связи не дублируются, дата не меняется.

### Совместимость и дозаполнение

Существующая база PostgreSQL хранит кейс в JSONB. Новое поле связей по умолчанию пустое, поэтому старые записи открываются сразу. Команда `python -m aidigest enrich --limit N` дозаполняет до `N` существующих кейсов за запуск. С `--offline` она использует только кеш. Дозаполнение запускается отдельно от регулярного сборщика, без новых запросов Tavily. На один кейс возможны до двух запросов к LiteLLM с учётом штатного повтора при некорректном ответе. При нехватке материалов кейс сохраняет имеющиеся данные, при ошибке его можно повторно обработать. Сборщик и дозаполнение используют общую блокировку записи PostgreSQL.

API списка возвращает данные для отображения всех показателей, типы эффектов, связи с KPI и дату обновления. Справочник фильтров выдаёт API. Для совместимости прежние поля ответа `first_seen`, `headline` и `headline_unverified` сохраняются. Экспорт Excel сохраняет текущую структуру в этом выпуске.

## Приёмка

- В таблице есть «Обновлён» и «Показатели». Колонок «В базе с» и «Главная цифра» нет. В таблице и карточке совпадает дата обновления конкретного кейса.
- Добавление подтверждения или даты источника обновляет кейс. Повторное сохранение тех же данных и проверка без новых материалов дату не сдвигают.
- Карточка показывает даты первичного и подтверждающего источников при наличии, корректно отображает старые записи без дат и не выдаёт дату события за дату публикации.
- Фильтр находит кейс по любой из его метрик или связей, работает в сочетании с текущими фильтрами и восстанавливается из URL. Кейс с показателями без связи со Стратегией доступен через «Тип эффекта».
- Недопустимый ID, вымышленная цитата, чужой URL и недопустимый для KPI вид свидетельства отклоняются при проверке ответа. Для смысловых критериев готовятся эталонные примеры с положительными и отрицательными связями. Проверка полного перечня KPI и тесты с подменами LLM выполняются без сети.
- Пакетное дозаполнение можно повторить без потери старых данных, изменения дат на холостом проходе, дублей и новых запросов Tavily.
