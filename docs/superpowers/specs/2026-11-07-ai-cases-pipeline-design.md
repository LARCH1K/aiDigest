# Пайплайн сбора кейсов внедрения ИИ — design

Дата: 2026-11-07. Статус: черновик на согласование.

## Зачем

Команда «Аналитика» вручную собирает кейсы внедрения ИИ на трёх уровнях: **мир**, **регионы РФ**, **Свердловская область** (все три одинаково важны). Наша цель — чтобы этот процесс в дальнейшем выполнялся автоматически. Контекст и вводные данные описаны в `CLAUDE.md` и `Вводные данные/md/`.

Ручной процесс «Аналитики» состоит из пяти шагов:
1. Найти источники.
2. Оценить их (достоверность, тип информации, частота обновления).
3. Выбрать методику: по каким показателям мерить эффект.
4. Собрать кейсы с цифрами и стадией внедрения.
5. Найти подтверждение цифр в других источниках.

Как мы распределили шаги:
- **Шаги 1–2** — справочник источников. По словам пользователя, он меняется редко, поэтому его делаем один раз и правим руками.
- **Шаг 3** уже сделан «Аналитикой»: Указ № 490, бизнес-метрики, М-1 и Р-1 из презентации. В пайплайне он служит «линейкой» для разметки показателей.
- **Шаги 4–5 — основной упор.** Они выполняются регулярно, и автоматизировать нужно именно их.

**Успех на показе «Аналитике»** (через несколько дней; формулировка — догадка, пользователь с ней согласился):
- аналитики видят таблицу кейсов в духе `рос и рег.docx` и узнают свою работу: из статей по эталонным кейсам Челябинска и Белгорода автоматически извлечены те же цифры;
- регулярный цикл находит свежие кейсы по всем трём уровням, включая Свердловскую область, которых у них самих нет;
- реакция: «можно брать, нам осталось только проверить».

*Решение Claude:* от регулярного цикла не требуется самому находить эталонные кейсы. Они старые, и под них пришлось бы подгонять запросы и окно свежести. Эталон проверяет качество извлечения, а цикл — поиск свежего.

## Цели

- Одна команда запускает регулярный цикл: сбор → извлечение кейсов → подтверждение → дедупликация → обновление базы → выгрузка в Excel.
- Каждый кейс содержит: место, отрасль, технологию, суть, стадию, измеримые показатели «было → стало» с привязкой к критерию методики, источники с достоверностью и статус подтверждения.
- Всё, в чём система не уверена, **помечается флагом, а не выбрасывается** (решение пользователя).
- Повторный запуск дописывает в базу только новые кейсы, а известные обновляет новыми подтверждениями.
- Качество можно проверить: на эталонных кейсах пайплайн вытаскивает те же цифры, что нашли аналитики.

## Не цели (сейчас)

- Автоматическое обнаружение и классификация новых источников. Справочник поддерживается вручную.
- Веб-интерфейс, расписание, развёртывание на сервере (сервера пока нет).
- Яндекс.Поиск (доступа нет), FRIDA (доступа нет), ГигаКоворк (доступа нет). Архитектура не должна мешать подключить их позже: поиск и сравнение кейсов спрятаны за простыми интерфейсами.
- Автоматизация шага 3 (методик).

## Анти-цели (провал, даже если «работает»)

- **Выдуманные цифры.** Показатель без дословной цитаты из источника в итоговой таблице недопустим: либо он подтверждён цитатой, либо помечен флагом.
- **Исчерпание лимита Tavily.** Лимит — 1000 кредитов в месяц на всё, включая отладку.
- Чтение, вывод или коммит `litellm.env` / `tavily.env`.

## Ограничения

- **Python.** LLM — через LiteLLM Proxy (OpenAI-совместимый, по умолчанию `GigaChat-3-Pro`); пример в `test_litellm.py`. Креды загружаются в рантайме из `litellm.env` (`LITELLM_API_KEY`, `LITELLM_BASE_URL`, `LITELLM_MODEL`) и `tavily.env` (`TAVILY_TOKEN`), тем же парсером, что в примере. Claude эти файлы не открывает.
- **Tavily** используется только при реальных запусках и отладке пайплайна. Документацию, ссылки на эталонные статьи и источники по Свердловской области при разработке ищем другими средствами (WebSearch/браузер).
- **LLM** тоже вызывается только при запусках и отладке. Лимиты есть, но не критичны.
- **Бюджет одного регулярного запуска** — около 30 кредитов Tavily. При еженедельном запуске это примерно 130 в месяц, остальное остаётся на отладку. **Первый запуск** (пустая база) — до 100 кредитов (решение пользователя); задаётся параметром запуска. Лимит на запуск задаётся в конфиге и соблюдается жёстко: при исчерпании пайплайн останавливает сбор и обрабатывает уже собранное.
- Все ответы Tavily и LLM кешируются на диск. Повторный прогон на тех же данных не тратит ни кредитов, ни вызовов LLM.
- Кириллица в путях и данных. Всё в UTF-8; в Windows-консоли вывод переключать на UTF-8.

## Как устроено (решения согласованы с пользователем)

### 0. Справочник источников (редко меняется)

Файл конфигурации со списком источников. Для каждого источника: название, домен(ы), уровень, достоверность (высокая / средняя / низкая), тип информации (официальная / статистика / кейсы / аналитика рынка / СМИ), частота обновления.

Начальное наполнение:
- источники из `Вводные данные/md/` (список, достоверность, «получаемая информация», презентация);
- региональные СМИ из эталонных кейсов: gubernia74.ru, chel.kp.ru, chr.rbc.ru, itrussia.media, нацпроекты.рф, realnoevremya.ru;
- **источники по Свердловской области**, которые найдёт builder (своими средствами, не через Tavily): официальные порталы области и Екатеринбурга, Минцифры области, региональные деловые СМИ.

Противоречия в данных «Аналитики» решаем так:
- Reuters — «средняя»: это новости, а не первоисточник;
- «Цифровой регион» — «средняя».

### 1. Сбор

- Для каждого уровня в конфиге задан набор поисковых запросов на русском и английском. Часть запросов ограничена доменами из справочника, часть открытая.
- Окно свежести — материалы за последние N дней (в конфиге).
- Tavily сразу возвращает текст страниц.
- Ответы кешируются по ключу запроса.
- URL нормализуются, уже обработанные ранее страницы повторно в LLM не отправляются.

### 2. Извлечение (LLM)

На каждую статью LLM получает её текст и описание методик. Методика выбирается по **сектору** кейса, который определяет LLM (поле `сектор`: госсектор / бизнес):
- госсектор, мир → М-1;
- госсектор, регионы РФ и Свердловская область → Р-1;
- бизнес, любой уровень → бизнес-метрики (ROI, затраты, время, ошибки).

*Решение Claude:* сектор определяет LLM по содержанию, а не тип источника. Например, Витрина AI Russia содержит и госкейсы. Методика у кейса ровно одна.

KPI Указа № 490 — макропоказатели страны. Для разметки отдельных кейсов они не подходят и в пайплайне не используются.

Задача LLM: определить, описан ли в статье **конкретный кейс внедрения ИИ** (кто, где, что сделано). Общие новости, мнения и анонсы рынка кейсами не считаются и отбрасываются. Это единственное место, где что-то отбрасывается, и в отчёте о запуске считается, сколько статей так отсеяно.

Из одной статьи может получиться несколько кейсов. По каждому LLM возвращает данные по схеме ниже. **Каждый показатель сопровождается дословной цитатой.**

### 3. Проверка цифр в тексте (код, без LLM)

Для каждого показателя код проверяет:
- цитата есть в тексте статьи (с нормализацией пробелов, кавычек, регистра);
- числа показателя есть в цитате (с нормализацией: «2,5» / «2.5», «9 млн» / «9 000 000», пробелы в числах).

Не прошло проверку → флаг `цифра_не_найдена_в_тексте`.

### 4. Подтверждение

- Для каждого **нового** кейса с хотя бы одним показателем — один дополнительный поиск Tavily: регион + организация + технология, исключая домен исходной статьи.
- LLM сверяет найденные тексты с показателями кейса и ставит статус кейса:
  - `подтверждено` — хотя бы один ключевой показатель совпал во втором независимом источнике;
  - `противоречие` — второй источник даёт другую цифру по тому же показателю; обе цифры сохраняются;
  - `один_источник` — ничего не нашлось.
- Найденный источник добавляется в кейс (как в эталоне: chel.kp.ru подтверждает gubernia74.ru).
- Если кредиты на запуск закончились, подтверждение откладывается: флаг `подтверждение_не_проводилось`, повтор при следующем запуске.
- *Решение Claude — порядок расхода бюджета:*
  - примерно 40% кредитов запуска заранее резервируются под подтверждение, сбор не может их потратить;
  - очередь подтверждения: сначала новые кейсы с показателями, потом отложенные (`подтверждение_не_проводилось`), потом повторный поиск для кейсов `один_источник`;
  - повтор для `один_источник` — не чаще раза в 4 недели и не более 2 повторов на кейс, только из остатка бюджета;
  - в схему кейса добавляются поля «число попыток подтверждения» и «дата последней попытки»;
  - неизрасходованный резерв подтверждения в конце запуска не переносится на сбор.

### 5. Дедупликация и слияние

- Новый кейс сравнивается с базой: кандидаты отбираются по уровню + региону/стране + нормализованному названию организации/системы, затем LLM попарно решает «тот же кейс или нет».
- Тот же кейс → источники и показатели сливаются в существующую запись, а второй источник может перевести её в `подтверждено`.
- Сравнение спрятано за интерфейсом, чтобы позже заменить его на эмбеддинги FRIDA.

### 6. Хранение и выгрузка

- База кейсов — один JSON-файл в репозитории (человекочитаемый, виден в git-диффе). Кеш Tavily/LLM — отдельная папка, в git не попадает.
- Каждый запуск выгружает Excel:
  - лист «Кейсы» — одна строка на кейс: уровень, регион/страна, организация, отрасль, технология, суть, стадия, показатели (текстом «было → стало, критерий»), статус подтверждения, флаги, ссылки;
  - лист «Показатели» — одна строка на показатель;
  - лист «Отчёт запуска» — кредиты Tavily, вызовы LLM, статей обработано / отсеяно, кейсов новых / обновлённых, распределение по флагам.
- В таблице кейсы с показателями и подтверждением идут первыми.

### Схема кейса

- `id`, дата первого обнаружения, дата последнего обновления.
- `уровень`: мир / регионы РФ / Свердловская область. Кейсы Свердловской области относятся к своему уровню, а не к «регионам РФ».
- `страна`, `регион`, `муниципалитет` (если есть), `организация`, `сектор` (госсектор / бизнес), `отрасль`, `технология ИИ`, `название`, `суть` (2–3 предложения).
- `попыток_подтверждения`, `дата_последней_попытки_подтверждения`.
- `стадия`: в разработке / пилот / внедрён / масштабирование / неизвестно.
- `показатели[]`: название; критерий методики (для Р-1 — скорость / качество / объективность / экономическая эффективность / персонализация; для М-1 — его шесть параметров; для бизнеса — ROI / затраты / время / ошибки); значение «было», значение «стало» или изменение; единица; вид (факт / план); дословная цитата; URL источника; прошла ли проверка в тексте; какими источниками подтверждён.
- `источники[]`: URL, домен, заголовок, дата публикации, достоверность и тип из справочника (неизвестный домен → `не_оценена`).
- `статус_подтверждения`: подтверждено / противоречие / один_источник.
- `флаги[]`:
  - `цифра_не_найдена_в_тексте`;
  - `противоречие_источников`;
  - `один_источник`;
  - `стадия_неясна`;
  - `нет_измеримых_показателей`;
  - `источник_не_оценён`;
  - `подтверждение_не_проводилось`.

### Проверка качества (эталон)

Эталонный набор строится из пяти кейсов `рос и рег.docx`:
- Челябинская обл. — пробки и ДТП;
- Белгородская обл. — цифровой двойник водоснабжения (два источника);
- Татарстан — «ГосПромпт».

Builder сам находит точные URL статей (своими средствами) и записывает ожидаемые показатели: 13 → 5 мин; 161 → 122 ДТП; −23% длительных отключений; >9 млн руб.; >90% точность; >230 объектов; 426 госслужащих / 25 ведомств.

*Решение Claude:* тексты эталонных статей скачиваются обычным HTTP-запросом (с извлечением основного текста страницы) и сохраняются в кеш один раз, кредиты Tavily на это не тратятся. Если страница не скачивается (защита от ботов), текст сохраняется вручную в файл эталона.

Отдельная команда прогоняет извлечение на этих статьях (через кеш) и отчитывается, какие ожидаемые цифры найдены. Цель — найдены все ключевые цифры, ни одна не выдумана.

### Запуск

Команды консоли:
- **регулярный цикл**;
- **прогон эталона**;
- **выгрузка Excel из базы** без поиска.

Параметры: лимит кредитов на запуск, окно свежести, выбор уровней. Есть сухой режим: только из кеша, без внешних вызовов.

## Что оставлено builder'у

- Структура пакета, имена модулей и команд, формат конфигов (YAML/TOML).
- Конкретные поисковые запросы и их распределение по уровням в рамках бюджета.
- Как добиться структурированного JSON от GigaChat: `response_format`, если LiteLLM/GigaChat его поддерживает, иначе парсинг + валидация `pydantic` + один повтор.
- Режим поиска Tavily (`basic`/`advanced`) и точная стоимость вызовов — проверить по документации Tavily.
- Правила нормализации чисел и цитат.
- Начальный список источников по Свердловской области.
- Тесты: юнит-тесты на чистую логику (нормализация, проверка цитат, дедупликация, бюджет, слияние) без сетевых вызовов; внешние вызовы — через фейки и кеш.
