# Веб: новые колонки в таблице кейсов, страницы «Запросы» и «Источники» — план

Согласовано в чате 08.11.2026 (небольшое изменение, без отдельного дизайна). Только чтение, редактирования через веб нет.

**Goal:** в таблице кейсов видны «В базе с» и «Достоверность»; две новые страницы показывают `config/queries.yaml` и `config/sources.yaml` с пояснениями полей.

**Ограничения:** `src/aidigest/` не меняется, фронт только импортирует оттуда (`load_queries`, `SourceRegistry`, модели). Тексты на русском. Без новых зависимостей. Битый YAML не даёт 500: страница открывается с сообщением.

## Решения

- «В базе с» = `Case.first_seen`, формат `дд.мм.гггг`. Сортировка по ISO-дате.
- «Достоверность» = лучшая оценка среди источников кейса. Порядок: высокая > средняя > низкая. «не_оценена» не считается. Если оценённых нет, показывается «нет оценённых».
- Фильтр «Достоверность» в таблице кейсов: любая / высокая / средняя / низкая / нет оценённых. Сравнивается с лучшей оценкой.
- Сортировка в `app.js`: если у ячейки есть `data-sort-value`, сортировать по нему, иначе по тексту. Нужно для дат и рангов достоверности.
- Каталог конфигов: `app.config["CONFIG_DIR"]`, по умолчанию `PROJECT_ROOT / "config"`. В `create_app(..., config_dir=None)` его можно переопределить для тестов.
- Источник с `level: null` подходит уровням РФ (см. `SourceRegistry.domains_for`). На странице он подписан «регионы РФ и Свердловская область».

## Задачи

### 1. Колонки и фильтр в таблице кейсов
- `views.py`:
  - `best_reliability(c: Case) -> Reliability | None`;
  - `RELIABILITY_LABEL` (`None` → «нет оценённых»);
  - `filter_cases(..., reliability: str = "")`, где значения — `высокая|средняя|низкая|none`.
- `routes.cases`: параметр `reliability`.
- `cases.html`: колонки «В базе с» и «Достоверность», select фильтра.
- `app.js`: `data-sort-value`.
- Тесты:
  - `test_best_reliability_prefers_high`;
  - `test_best_reliability_none_when_only_unrated`;
  - `test_reliability_filter` (включая `none`);
  - `test_list_shows_first_seen_and_reliability` (страница содержит `01.11.2026` и «средняя»).

### 2. Страница «Запросы» (`/queries`)
- `load_queries(CONFIG_DIR / "queries.yaml")`, группировка по `Level` в порядке enum.
- Колонки: текст запроса, «Только по справочнику» (да/нет), язык. Справка над таблицей и пояснения к полям.
- Пункт меню «Запросы».
- Тесты:
  - `test_queries_page_lists_real_queries` (текст первого запроса из реального `config/queries.yaml`, заголовок пояснений);
  - `test_queries_page_survives_broken_yaml`.

### 3. Страница «Источники» (`/sources`)
- `SourceRegistry.load(CONFIG_DIR / "sources.yaml").sources`.
- Фильтры: уровень (включая «регионы РФ и Свердловская область» для `null`) и достоверность.
- Сортируемые колонки: название, домены, уровень, достоверность (с рангом), тип, частота.
- Справка: что такое справочник, откуда оценки, значения достоверности и типов; источник вне справочника получает «не оценена».
- Пункт меню «Источники».
- Тесты:
  - `test_sources_page_lists_registry` («TAdviser»);
  - `test_sources_filter_by_reliability` (`?reliability=высокая` убирает TAdviser);
  - `test_sources_page_survives_broken_yaml`.

### 4. Справка и проверка
- `help.html`: пояснения к «В базе с» и «Достоверность», ссылки на новые страницы.
- Полный pytest, проверка в браузере (`.claude/launch.json`, кнопку сбора не нажимать), ревью диффа.
