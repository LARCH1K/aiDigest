# План реализации дат кейсов и KPI Стратегии

> Реализация по задачам через `superpowers:executing-plans` или `superpowers:subagent-driven-development`. Проверки пишутся до реализации.

**Цель** — искать кейсы по типу эффекта и KPI Стратегии и видеть даты обновления кейса и публикации его источников.

**Архитектура** — пайплайн заполняет существующие даты и сохраняет подтверждённые материалами связи в JSONB кейса. FastAPI выдаёт данные и применяет фильтры, React отображает список и карточку.

**Стек** — Python, Pydantic, PostgreSQL, FastAPI, React, Vitest.

**Спецификация** — [даты кейсов и KPI](../specs/2026-11-16-case-dates-and-strategy-kpi-design.md).

## Ограничения

Перечень KPI берётся из пункта 28.1 Стратегии. Схема таблиц, экспорт Excel и старые поля ответа списка совместимы. Для дат публикации допустимо пустое значение. Тесты без внешних запросов, дозаполнение без новых вызовов Tavily.

## Особые случаи для проверки

- Повтор подтверждения без новых данных сохраняет дату обновления.
- Старая запись с ISO-временем, пустой или ошибочной датой публикации открывается.
- Повторная классификация с частично ошибочным ответом сохраняет старые связи и добавляет валидные новые.
- Без исходного текста непроверенная цитата из старой записи не становится свидетельством.
- KPI без чисел виден при выборе KPI по умолчанию, `metrics=1` явно скрывает его.
