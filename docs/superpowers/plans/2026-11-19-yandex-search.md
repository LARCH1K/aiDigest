# План реализации поиска через Yandex Search API

> Для реализации использовать `superpowers:executing-plans` или `superpowers:subagent-driven-development`. Вести отметки по шагам.

**Цель** — сделать Яндекс поиском по умолчанию, сохранить явный выбор Tavily и убрать названия провайдеров из веб-интерфейса.

**Архитектура** — оба клиента реализуют существующий `SearchClient`. CLI и API читают одну настройку из окружения, а подпроцесс сбора наследует её. Поисковые ответы кешируются раздельно, тексты страниц используют существующий HTTP-кеш.

**Стек** — Python, requests, стандартный XML-парсер, trafilatura, FastAPI, React, Docker Compose.

**Дизайн** — [поиск через Yandex Search API](../specs/2026-11-19-yandex-search-design.md).

## Общие ограничения

- `AIDIGEST_SEARCH_PROVIDER` принимает `yandex` (по умолчанию) или `tavily`. Каждый запуск использует один провайдер даже при ошибке. Неизвестное значение — ошибка конфигурации.
- `YANDEX_SEARCH_API_KEY` и `YANDEX_SEARCH_FOLDER_ID` загружаются из окружения или `secrets.env`. Тесты подменяют сеть, секреты передаются только при работе сервиса.
- Проверить пять пограничных случаев: неполный XML и пустая выдача (задача 1), недоступная статья (1), пустой офлайн-кеш (1), исчерпанный лимит Tavily (2), старые имена провайдера в исторических журналах и отчётах (3).
